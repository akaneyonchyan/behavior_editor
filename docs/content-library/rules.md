# 使用规则与数据结构

更新日期：2026-10-19。实现依据：shared/library-model.mjs、server/feishu.mjs、src/store/contentLibrary.js。

## 定义边界

对象表示属性的载体或设计筛选类别；实际实体与筛选类别不是一一对应。例如手持关系不新建实体，食物/原料可能是用途子类。交互场所与资产内交互点位独立区分，不能为了下拉方便复制同一实例的属性。

属性表示对象可以读取的状态值；当前库字段只有数值/枚举两种类型。Buff 是独立的临时效果定义，不因为名字像状态就改成普通属性。品质、库存、装备、点位占用等业务字段不应全部塞进属性表。

2026-10-19：按用户明确要求，对象类型新增启用项“Buff”（稳定标识 buff），用于引用 Buff 本身。原 Buff 类型表继续维护效果定义及适用对象，不自动改动其关联。本次仅新增对象类型，未配置该类型的属性或具体对象名录；对象表ID留空，不将基础 Buff 表直接填作对象名录表。

库描述“是什么、适用谁”；行为描述“何时、对谁、如何改变”。库不反挂每个行为的结算规则，不承担精确权重或平衡数值设计。

2026-10-19用户明确决定：布尔状态在编辑器中按枚举表达；本次将晕眩、生病、新的(物品)、装备槽、拥有原料、交互点位占用六项的数据类型统一为“枚举”，保留原标识、说明、启用状态及适用对象。该转换仅用于设计工具候选类型，不把工程中的对象引用、JSON或数组改造成运行时枚举，也不表示通用JSON/数组编辑已受支持。今后新增类型需先更新编辑器与校验器，否则会阻断整个公共库发布。

## 飞书字段与 JSON 映射

| 飞书字段 | JSON 字段 | 使用范围与规则 |
|---|---|---|
| 标识 | id | 三表都有；推荐稳定英文标识，不能用改 ID 的方式重命名 |
| 名称 | name | 三表都有；同表内非空、唯一，最长200字符 |
| 说明 | description | 三表都有；文本，最长10000字符 |
| 启用 | enabled | 三表都有；复选框，只有 true 才作为启用 |
| 数据类型 | kind | 属性表专用；单选“数值”或“枚举” |
| 适用对象 | objectTypes | 属性/Buff 表；关联对象表，可多选；不要用普通名称文本代替关联 |

对象表不需要数据类型或适用对象。标识最长200字符、同表唯一。读取器兼容空标识回退到飞书 record_id，但日常维护应显式填写稳定标识，避免复制表后引用失效。已有使用回退 ID 的记录，不可直接补填新 ID 而不迁移行为引用。

快照结构为 { syncedAt, library }；library 包含 version:1、objects、attributes、buffs。各表最多10000行。所有行都会校验并发布，包括停用行；停用不是隐藏信息或绕过校验的方法。

适用对象为空合法，表示没有对象能在正常筛选中选到该条目；失效关联会导致发布失败。当前读取器只读取上表字段；可在飞书增加“来源”等管理字段，但不会自动出现在网页，关键解释应同步写进“说明”。

## 引用与下拉

编辑器保存稳定标识而非仅保存名称：对象来源统一使用 object:<对象ID>，Buff 引用使用 buff:<Buff ID>。对象、属性和 Buff 的候选项只来自当前公共库启用条目，不额外注入执行伙伴、互动伙伴等角色选项。旧 actor/partner 等引用仅兼容读取，显示为非候选原值供整理，不静默合并对象身份。新规则来源留空等待选择。

先选来源，再按对象类型筛选 enabled=true 且 objectTypes 包含该类型的条目。结果的属性/Buff分栏会进一步区分种类。停用对象或条目会退出候选，但历史引用需要保留；旧名称显示或 ID 回退不代表它仍可正常用于新设计。

自定义输入可以继续保存，并显示下划线。维护者应收集这些需求，核对来源后决定新增、复用或保留为行为描述，不能自动批量转成公共库条目。

## 条目说明建议格式

建议在“说明”里依次填写：含义；适用载体；值来源（保存/计算/外部读取）；可写性；规则文档章节；工程映射及证据；待确认项；修改日期。

示例编号必须标注“示例”，不能当正式工程 ID。编辑器英文标识也不是游戏数值 ID。当前库没有结构化的取值来源、只读标记、枚举值列表字段，相关约束暂写说明，不应宣称界面已全部强制校验。

## 变更原则

- 改显示名保留 ID；先搜索已有行为引用，再做兼容性评估。
- 淘汰条目优先停用，不直接删除；删除对象还会破坏属性/Buff关联。
- 新含义另建新 ID，不能把旧 ID 改作另一种属性。
- 未确认的工程映射可记为待核对；不要猜测编号、默认值和实际支持状态。
- 不给缺失属性默认赋0，也不把缺失对象替换成执行伙伴。这是设计与接入要求，编辑器本身不运行读取结算。

发布版首次渲染不加载内置示例库；仅使用已验证的发布快照或该快照的本机缓存。播放方式、增减、影响方式等是编辑器规则选项，不属于公共库对象／属性／Buff目录；自定义输入能力仍保留并以下划线标记。

## 对象名录（2026-10-19）

对象类型是分类，具体对象名录按类型分表维护。对象类型表新增文本字段“对象表ID”，填写同一 Base 中对应对象表的 table_id；不按表名猜测映射，不为每张新表增加 Secrets。同一表不能重复关联多个类型；不得指向对象类型、属性或 Buff 基础表。留空表示该类型尚无名录。

每张对象表字段：名称（文本主列）、标识（文本）、说明（文本）、启用（复选框）。名称在同一对象表内非空且唯一；不同类型可以同名。标识建议首次填写稳定值；不填则使用 record_id，已经被引用后不要补填或修改标识。改名称保留标识，停用退出候选而保留历史引用。空表合法，不生成示例记录。

快照新增可选 items 数组，每行 {id,objectType,name,description,enabled}。id 由 encodeURIComponent(对象类型ID) + '/' + encodeURIComponent(对象条目标识或record_id) 组成，避免不同表使用相同局部标识时冲突。对象名最长200字符、说明最长10000字符；单表最多10000条、items 总数最多100000条。对象表ID仅服务端读取，不进入公开快照；对象名录内容和停用行均会公开。

行为字段 objectName 保存 item:<名录ID> 或自由填写文字；旧文件缺少此字段合法。先按来源/对象类型筛选名录，仅启用类型及启用对象作为候选。改名自动显示新名称；停用、换类型或失效引用保留并加下划线，不能按同名条目静默改绑。留空不限定具体对象，不是新增“任意对象”条目。对象名录是设计引用目录，不保存运行时实例属性值。
