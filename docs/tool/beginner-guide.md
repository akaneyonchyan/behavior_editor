# 行为编辑器小白上手手册

按顺序完成四件事：找到仓库 → 克隆到电脑 → 使用编辑器 → 用 Cindy 修改编辑器。更新：2026-10-26。

## 2. 怎么克隆到自己的电脑

“克隆”就是把项目文件和修改历史下载到自己的电脑。每个人克隆自己的副本，不共用别人的工作目录。只使用在线编辑器可以跳过这一步；修改编辑器需要克隆。

### 推荐：让 Cindy 帮你克隆

1. 在电脑上准备一个存放项目的文件夹，例如 Windows 的 `C:Projects`；也可以用自己已有的目录。
2. 在 Cindy 新建任务，把工作目录选为这个文件夹。
3. 把下面整段发给 Cindy：

> 请检查这台电脑是否已安装 Git，然后把 https://git.xindong.com/petpals/shared/design_behavior_editor.git 克隆到当前目录下的 design_behavior_editor 文件夹。若目录已经存在，先检查是不是同一仓库，保留已有文件和未提交修改，不要覆盖。完成后告诉我项目文件夹的完整路径。如果需要 GitLab 登录，请引导我在正规的登录或凭据窗口完成，不要让我把密码或令牌发到聊天里。

4. 按提示用自己的 GitLab 账号完成认证。公司若要求个人访问令牌，请按公司指引配置到凭据管理器，不填进克隆地址或聊天。
5. 克隆完成后，在 Cindy 中把工作目录切换到返回的 **design_behavior_editor 项目文件夹**，后续开发都在这里进行。

**完成标志：** 文件夹内能看到 `README.md`、`AGENTS.md`、`package.json`、`src` 和 `docs`。只连接 Cindy GitLab 插件，不等于已经把仓库克隆到电脑。

### 也可以自己用命令克隆

先安装 Git。Windows 在要存项目的文件夹打开 PowerShell；macOS／Linux 打开终端并进入目标文件夹。逐行执行：

```sh
git clone https://git.xindong.com/petpals/shared/design_behavior_editor.git
cd design_behavior_editor
git status
```

第一行下载项目，第二行进入项目目录，第三行检查当前状态。出现认证失败或无权访问时，先检查账号及项目权限，不要反复覆盖下载，也不要关闭 TLS 证书校验。

## 3. 怎么使用编辑器

### 日常画行为图：直接打开在线版

1. 用电脑 Edge 或 Chrome 打开上面的在线编辑器地址，使用心动 SSO 登录。
2. 按提示选择自己的本地保存目录；想先试用可以选择“暂用浏览器草稿”。
3. 想看现成图：在左侧文件区选择“在线”，点击一个行为文件。在线图只读；想修改它，先“另存为”到自己的目录，再从“本地”或“打开”读取副本。
4. 想从头画：先保存当前工作，再点“新建”。点击开始节点或画布空白处，在右侧填写行为名称和准入数据。
5. 从左侧拖入节点，点击节点后在右侧填写内容；从前一个节点的出口拖到后一个节点的入口建立连接。
6. 点击“保存”生成正式 JSON 文件。重新打开这个 JSON 可以继续编辑；“导出 PNG”用于给别人看图。

| 界面位置 | 用来做什么 |
|---|---|
| 顶部 | 新建、打开、保存、另存为、导出 PNG、查看需求清单 |
| 左侧 | 添加节点，选择本地或在线行为文件 |
| 中间 | 查看流程，选择节点，调整连线 |
| 右侧 | 编辑当前节点或行为的具体内容 |

**务必手动保存：** 草稿和自动缓存只是恢复辅助，不等于正式保存，也不会自动上传 GitLab或同步到同事电脑。JSON 用于继续编辑，PNG 用于阅读。网页上传当前关闭，需要共享行为文件时交给维护者按仓库流程审核。

具体节点和操作说明见 [使用方法](usage.md)。

### 想看到自己改的界面：启动本地版

本地版是运行在自己电脑上的编辑器，用于开发和检查改动。首次需要 Git、Node.js 22.13 或更新的兼容版本、npm（随 Node.js 安装）及浏览器。

在 Cindy 打开已克隆的项目目录，复制：

> 请读取 AGENTS.md、docs/tool/README.md、docs/tool/team-onboarding.md 和 .agents/skills/behavior-editor/SKILL.md，检查 Node.js 和 npm。按照当前 gitlab-static、published 公共库模式安装依赖、生成行为快照并启动本地编辑器，只监听 127.0.0.1，使用本地 base 路径 /。完成后告诉我可以打开的本地网址。保留我已有的修改，不部署网站，不改权限或飞书源表。公共库缺失时说明如何向维护者获取获授权的快照，不索要生产密钥。

打开 Cindy 返回的网址，通常为 `http://127.0.0.1:5173`，以实际启动输出为准。启动终端或服务停止后，本地地址会失效；再次使用时让 Cindy 重新启动。

如果自己操作，Windows PowerShell 在项目目录执行：

```powershell
npm ci
node scripts/export-behaviors.mjs
$env:VITE_ONLINE_PROVIDER='gitlab-static'
$env:VITE_LIBRARY_MODE='published'
$env:VITE_AUTH_MODE=''
$env:PAGES_BASE='/'
npm run dev -- --host 127.0.0.1
```

`npm ci` 安装依赖，首次准备或依赖变化时执行。其余命令准备行为快照并启动页面。macOS／Linux 的环境变量写法见 [开发入门](team-onboarding.md)。

公共库快照不随仓库分发。没有快照时可查看基础界面，但相关候选数据会未就绪。需要完整验证时向维护者获取获授权快照，再让 Cindy 按开发入门导入。普通开发不需要飞书 App Secret 或服务器密码。

## 4. 怎么修改编辑器

“修改行为图”是在页面里改 JSON；“修改编辑器”是改工具本身，例如按钮、布局、提示文字、节点编辑方式。以下步骤用于修改工具。

### 第一步：在 Cindy 里打开正确的目录

选择刚克隆的 `design_behavior_editor` 文件夹。每次开始新任务，让 Cindy 检查是否有未提交修改，再拉取最新远端信息并创建独立分支。分支可以理解为“本次修改的工作副本”，不会直接改变所有人使用的网站。

### 第二步：用人话说清楚要改什么

不用先学代码，但要说清三个点：改哪里、改成什么、怎样算改好。

例如：“把右上角退出按钮改成与旁边按钮一致的样式，账号与退出放在功能栏最右侧，中间用竖线分隔；检查窄窗口下不会重叠，退出仍然有效。”

把下面这段复制给 Cindy，替换方括号内的内容：

> 请按 behavior-editor Skill 工作，先读取 AGENTS.md、docs/tool/README.md 和 .agents/skills/behavior-editor/SKILL.md。检查当前仓库和未提交修改，保留已有工作，从最新 origin/master 创建独立任务分支。我要修改【具体位置】，希望变成【具体效果】，验收标准是【我能亲自检查的结果】。请完成代码修改，运行仓库要求的测试和构建，启动本地页面，告诉我查看地址与验证步骤。不要直接推 master，不部署网站，不修改飞书源表或权限。

第一次建议先改一处文案或小布局。复杂的保存机制、权限和数据结构修改要让维护者参与检查。

### 第三步：自己打开本地页面检查

1. 打开 Cindy 返回的本地地址。
2. 按你写的步骤操作，确认实际效果符合要求。
3. 检查相邻功能是否仍然正常。文件操作用测试副本，不用正式文件冒险。
4. 不符合要求就告诉 Cindy：“我做了什么、实际看到什么、希望看到什么”，让它修正后再次验证。

Cindy 说“完成”时，确认测试是否真的通过，有哪些未验证项目。此时正式网站还没有更新。

### 第四步：提交给同事审核

本地确认后，把下面这段发给 Cindy：

> 本地效果已验收。请检查差异，只提交本次相关文件，推送当前任务分支，并创建目标为 master 的 Draft MR。写清改了什么、测试结果及未验证项目，给我 MR 链接。不要直接合并或部署，不提交密钥、个人配置、构建产物或公共库快照。

MR 就是“请同事审核并合并这次修改”。需要 Cindy 直接操作 MR 时，在插件页给 Cindy GitLab 连接自己的账号；也可以先通过 Git 推送，再去仓库网页创建合并请求，目标选择 `master`。插件认证与本机 Git 认证可能需要分别配置。

### 第五步：审核通过，等待统一发布

由有权限的审核者合并到 `master`。指定维护者电脑上的 Cindy 会检查变更，通过测试、构建后发布到现有网站。合并成功不等于已经上线，以发布成功结果为准。

同事不用安装发布任务，也不需要生产发布凭据。维护者电脑关闭或 Cindy 退出时，新版本发布暂停，已经发布的网站仍可访问。

---

**最短操作路线：** 拿到 GitLab 权限 → 让 Cindy 克隆 → 把工作目录切到项目文件夹 → 日常使用打开在线网址 → 修改工具时让 Cindy 启动本地版 → 说清需求并验证 → 推分支、提 MR → 审核后统一发布。

更多权限、命令和故障说明：[同事开发入门](team-onboarding.md)。
