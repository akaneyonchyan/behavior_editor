# 行为编辑器使用与维护

把用户要求落实到当前工程或内容库，沿用其既有设计语义和本地文件工作流。项目文档是细节的唯一维护入口，按任务读取，不复制整套手册到 Skill。

## 定位工程与任务

仓库：https://github.com/akaneyonchyan/behavior_editor

站点：https://akaneyonchyan.github.io/behavior_editor/

先找实际工程根目录：通常是本 Skill 所在 .agents 的上级目录；若 Skill 安装于更大的工作区，则检查当前目录或用户指定项目中的 package.json、src/store/documentSession.js、docs/tool/README.md。用文件检索排除 node_modules、dist 和 .git。存在多个候选时，结合 Git remote、用户正在使用的版本和文档确认，不任意选择旧原型。

有 Git 时检查 status、diff 和远端；无 Git 时检查实际文件并记录它只是源码副本。修改前读工程 AGENTS.md。后文路径均相对工程根目录，不相对 Skill 安装目录。

若没有工程，使用已授权的 GitHub 读取能力或公开仓库文档回答使用问题；代码改动需要可审阅的工作副本。没有飞书权限不影响代码和文档工作，但不能声称已核验或修改飞书数据。

| 用户任务 | 按需读取 |

文档缺失时从上述仓库取对应文件；无法取得就明确未核验范围。真实源码优先用于判断现有实现，设计语义需结合最新明确需求和规则来源，不把旧实现当成不可变需求。

## 使用与行为图协助

给出当前界面能执行的步骤。操作现有行为图前确认目标文件/页面，保留未保存内容；演示和验证用测试图。处理用户提供的 JSON 时先按 documentValidation.js 检查结构，保留不认识的自定义文字和兼容字段，不覆盖原件来试验。

重点区分：首次与新建均为完整空白模板、正式文件、浏览器草稿、固定磁盘缓存。自动缓存不是正式保存，也不会跨设备同步或提交 Git。“恢复草稿”读取浏览器记录，不扫描磁盘文件；磁盘 JSON 用“打开”或左侧节点列表下方“本地行为文件”区读取。文件区只列保存目录直接子文件，不进入自动缓存目录；切换复用未保存确认及原文件冲突保护。

多个标签页各自保留浏览器草稿；磁盘当前快照共享。旧的随机编号恢复文件可含未保存内容，不批量删除。用户询问异常时先用代码和文件证据定位，不能把截图中另一台设备的文件说成本机已检查。

产品术语统一使用“行为准入数据”和“行为设计节点”。后者指用于设计行为的节点，不沿用项目已有其他含义的“节点图”。内部 JSON 键与源码标识可保持兼容，不能因文案更名破坏旧文件。

## 修改编辑器

根据 development.md 定位模块，沿着默认数据→编辑面板→状态更新→节点摘要→导入导出/迁移检查完整路径。局部修改只处理相关路径，不顺便重构整个工程。

当前关键约束（用户明确变更时再调整）：

- 配置排序复用 SortableList：仅组内、手柄启动、松开一次提交；保留分支ID/连线、共享属性影响及自定义值。第一批覆盖通用规则、判断和执行输出，其他列表按任务接入。

- 产品服务规则与定性期望，不擅自恢复精确概率/系数输入或宣称游戏运行时可直接执行。
- 下拉允许非候选输入并加下划线，显示名称变化不能丢失稳定引用。
- 开始节点唯一、蓝色、不可删除复制；行为准入数据由开始节点和未选节点时的右侧面板编辑。
- 判断的共享属性传给各分支，分支只表达默认概率与影响方式；结果的属性/Buff/产物独立显示，空输出不占位。
- 循环按目标、准入、稍息有序判定；准入与稍息默认启用，可独立关闭。关闭隐藏对应步骤及出口连线，保留配置以供重新启用；两个都关闭则目标未达成直接继续执行。
- 位移、寻路失败和外部监听中断属于行为外通用规则，新建不提供位移节点，也不预设中断结束。判断分支、执行后续、循环出口可标记“跳出行为”，与内部连线互斥；通用跳出不隐含收尾表演或资源释放。旧位移和旧中断表演须明确核对后迁移，不按名称自动删除，详见 docs/tool/development.md。
- 当前画布是贝塞尔流光；旧避障源码存在不代表当前启用。
- 正式文件只手动写入；自动缓存固定文件名，保留外部修改冲突保护和旧图迁移，不通过清空缓存修问题。

按改动补回归，运行 npm test 和 npm run build。UI或浏览器文件权限变更另验证真实交互，避免拿正式文件测试。纯文档/Skill改动只需格式、路径、事实和入口检查，不必增加镜像测试。

## 在线行为共享

在线文件按 docs/tool/online-files.md 使用：公开仓库 behaviors/main 只读预览，下载后本地编辑，选定文件上传经分支和 PR 审核。不要自动上传用户本地行为；不写 main、不自动合并；Token 仅用于上传且只在网页内存，不落盘。公开浏览和下载读取 Pages 静态发布目录，不调用 GitHub API、不要求授权；合并后等待 Pages 发布。在线文件在主画布直接只读加载，不用预览弹窗；文件区使用独立标题与平直页签，本地/在线切换保持顶部与左右栏尺寸稳定。预览使用隔离状态，不改本地缓存；覆盖需保留本地未保存保护与线上 SHA 核验。功能维护同时核对 API、下载、浏览器回归及 behaviors 校验工作流。

## 维护公共库

对象名录按对象类型表的“对象表ID”关联同一 Base 的独立表；稳定标识 buff 的类型可例外复用已有 Buff 基础表，同批读取生成名录，不复制记录、不改适用对象；空表合法，不代用户填充示例。objectName 可存稳定条目引用或自由文字，换类型/停用保留原值并加下划线。新增目录必须同步 items 校验、读取、刷新比较、摘要和兼容测试，详见公共库 rules.md。

对象来源、属性、Buff候选只取当前公共库的启用条目，不追加执行伙伴、互动伙伴等内置身份选项。新规则默认留空；旧身份引用仅兼容保留，不擅自合并其作用对象。

当前生产链路是飞书基础三表及按类型关联的对象名录→Actions快照→Pages只读查询；旧可写 Node 后台不在 Pages 运行。页面“刷新数据”只取已发布快照，不触发飞书或 GitHub 同步。计划约5分钟、页面约60秒检查，不承诺延迟上限。

改库前读取当前条目及来源原文，按 rules.md 区分对象载体、属性、Buff和业务字段。检查同义项和稳定 ID；维护方式优先停用而非删除，改名不改 ID，不能把旧 ID 复用于新含义。示例工程编号、未确认映射不得推定为已实现。

写入前的类型约束：属性表“数据类型”（JSON kind）当前只允许精确值“数值”“枚举”；布尔按枚举表达。工程中的 bool、对象引用、JSON、数组等不能直接作为此字段的值，应保留在说明中。已确认的枚举映射见 rules.md；没有明确映射的新结构不能一律猜成枚举。需要新增类型时，先完成读取转换、校验器、界面及兼容测试，再写生产数据。行为图下拉允许自定义文字，不代表公共库类型字段也允许自定义。

调用飞书新增／修改接口前，读取当前库及本次涉及的字段定义，将拟修改内容合并为编辑器快照格式，调用 shared/library-model.mjs 的 validateLibrary 校验；包含停用条目。格式示例与命令见 docs/content-library/maintenance.md。校验失败不写入，不能等 Actions 来发现错误；没有完整候选数据或当前校验器时，先输出待核对差异，不声称可安全写入。写后回读改动行并校验，再核对发布快照。此流程约束 Agent 操作，不能拦截其他人直接在飞书里的编辑。

根据来源新旧、适用范围和用户明确决策处理冲突。sources.md 中的历史核对日期不是实时确认。不能访问原文时先给待核对变更清单，不自动启用猜测条目。

实际写飞书需在用户当前授权范围内。形成可审阅的逐条差异：表、ID、旧值、新值、来源、引用影响；保留修改前数据于团队内部。若只有核对授权，完成差异即可，不写生产表。工具调用前查看实时插件说明，避免假定某环境必有相同连接器。

验证启用状态、适用对象关联、唯一性和类型；等待发布后检查 syncedAt、实际快照与对应节点候选。失败时保留已发布数据，按错误修复，不反复重跑来掩盖无效配置。公开快照包括停用条目，不把内部原表、密钥或不应公开的说明提交仓库。

## 提交、发布与交付

使用任务已授予的提交/部署权限；调用 Skill 本身不授予外部写入权限，不要求重复申请已有授权。未获发布授权时先完成本地可审阅改动及验证，再说明待发布项。

提交仅包含任务相关文件。密钥通过 Repository Secrets 管理，前端 VITE_ 变量、日志和文档中都不能放凭证。发布按实际 .github/workflows/pages.yml 运行；核对提交对应的运行与站点，不把推送成功当上线成功。授权/配置失败或同一确定性错误时停止重复尝试，说明原因及下一步。

交付用简短中文说明改了什么、实际验证了什么、是否已提交/上线、用户需要做什么；功能变化同步工程说明，语义变化同步公共库来源和迁移记录。

本 Skill 的共享源在仓库 .agents/skills/behavior-editor/。若安装了工作区副本，修改共享源后同步副本；不要单独维护多份流程。它可自动匹配相关任务，也可显式调用“使用 behavior-editor Skill …”。Cindy 的新建或重启会话可发现新安装的项目 Skill；其他宿主按各自的 Skill 加载方式使用。
